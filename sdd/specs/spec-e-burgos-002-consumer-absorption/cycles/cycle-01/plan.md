# spec-e-burgos-002-consumer-absorption — cycle-01 (c00) · plan (lite)

> Módulo: consumer-absorption | Subproyectos: libs/tucu-ui, libs/tucu-docs, tools/mcp-server | Fecha: 2026-10-27
> Objetivo: que las primitivas de tucu-ui se puedan usar sin wrappers ni `!important`: merge real de clases, `aria-*`/`data-*` en la raíz real, labels traducibles, tamaño `xs` y los bugs que reportó el Studio de sdd-harness (spec-e-burgos-009 cycle-01 → `issues_found`). Fuera de alcance: presets de marca y scope de tema (cycle-02), componentes nuevos (cycle-03).

## Historias
- US-001 — Como dev consumidor quiero pasar `className` con `h-*`, `bg-*` o `text-*` y que pise el default, para no forzar estilos con `!`. CA: `cn` con tailwind-merge en toda la librería; test que prueba la sobrescritura en Button, Input y Badge.
- US-002 — Como dev que escribe tests y features accesibles quiero que `aria-*` y `data-*` lleguen al elemento real (el `role=dialog`, el `<button>`, el `<input>`). CA: tests por primitiva.
- US-003 — Como usuario en español o francés quiero que los labels internos (cerrar modal, mostrar contraseña, acceso denegado) sigan el `lang` del tema. CA: ningún aria-label fijo en inglés en las primitivas tocadas.
- US-004 — Como dev de interfaces densas quiero un tamaño `xs` en Button, Input, Textarea, Badge y Spinner. CA: `size="xs"` con altura ≤ h-6/h-7 y `text-xs`.
- US-005 — Como dev consumidor quiero que Button, Modal, Input, Textarea, Select, Radio, Checkbox, Alert y Tooltip se comporten como se espera (lista de bugs del plan). CA: un test por bug.
- US-006 — Como dev que arranca una app quiero que el tema por defecto sea neutro, que el CSS de la librería no les gane a mis utilities, que el entry no me obligue a inlinear swiper en vitest y que el CSS exportado no pese ~727 KB. CA: colorScheme `default`, CSS en `@layer`, entry sin CSS de terceros y tamaño medido antes y después.

## Tasks (detalle en tasks.json)
- TASK-001 — Base transversal: `tailwind-merge` como dependencia; `cn()` en `src/libs/cn.ts` (classnames + tailwind-merge extendido con los tokens propios `text-13px` y `shadow-*`), exportado públicamente y usado por los 123 módulos que importaban `classnames`; el helper del datatable reexporta el mismo `cn`. i18n: claves `dialog.close` y `accessDenied.{title,description,action,login}` en en/es/fr; `AccessDeniedPage` y `AuthProvider` sin textos fijos en inglés.
- TASK-002 — Button, Badge, Spinner y Alert. Button: sin `<div>` envolvente cuando no hay tooltip (el drip queda dentro del `<button>`), `wrapperClassName` cuando hay tooltip, `type="button"` por defecto, tamaño `xs` con `text-xs`, `transparent` sin `bg-gray-100/25` fijo, `ghost` con borde de 1px (`outline` nuevo) y el border-2 actual intacto, `gray` solid con tono de superficie oscura en dark. Badge y Alert: tonos de estado `soft`/`ink`/`line` con tokens del tema. Alert: `live="polite"` → `role="status"`, sin `undefined` en className y passthrough de `aria-*`/`data-*`. Badge y Spinner con `xs`.
- TASK-003 — Modal y Tooltip. Modal: `aria-label`, `aria-describedby` y `data-*` al `role=dialog`; `title` acepta ReactNode y hay `header` libre; Escape escuchado en el diálogo con el foco adentro (y respetando modales anidados); click-afuera sobre el overlay que contiene al panel; cierre sin la demora de ~200 ms; `size` (`sm`/`md`/`lg`/`xl`/`full`) que reemplaza los `max-h-[60vh]` y `sm:max-w-[800px]` fijos, con el default actual; label de cierre desde `dialog.close`. Tooltip: el contenido queda siempre en el DOM (sin portal ni desmontaje), oculto con `hidden`/aria cuando está cerrado.
- TASK-004 — Input, Textarea, Select, Radio y Checkbox. Input: `aria-invalid` solo con error; `size="xs"`/`sm`. Textarea: `className` va al `<textarea>` como en Input y `wrapperClassName` al contenedor, conservando compatibilidad; `size`. Select: variante `native` con `<select>`/`<option>`, `aria-describedby` a helper/error. Radio y Checkbox: `items-start` con label multilínea; Radio con `id` y `htmlFor` generados con `useId`.
- TASK-005 — Tema, CSS y datos. `colorScheme` por defecto `default` (no `macos-tahoe`); `html.macos-tahoe p` no pisa el color heredado; `useTheme.getState().setMode` lee el estado actual y no el de montaje; popovers del header con `data-material="solid"`; CSS propio dentro de `@layer` para que las utilities del consumidor ganen; tokens `--tucu-toast-*` en Toast; `useColumns` del DataTable reparte solo el ancho sobrante entre las columnas sin `size`.
- TASK-006 — Entry y peso del CSS. Entry liviano sin CSS de terceros (el CSS de swiper se carga desde el Carousel o desde `./styles`, nunca desde el barrel de JS); `@source` acotado para que `./styles` deje de escanear todo el paquete. Medir el tamaño de `index.css` antes y después.
- TASK-007 — Integración: `generate-props`, registry del MCP (props nuevas: `size="xs"`, `wrapperClassName`, `tone`, `live`, `native`, `header`), página de cambios en tucu-docs, CHANGELOG, verificación con `pnpm tucu-ui:test-local` y `nx run-many -t lint test build`.

## Decisiones técnicas
- `cn` = `twMerge(classNames(...))` y no tailwind-merge solo → conserva la sintaxis de objetos/arrays de classnames que usan los 123 módulos. Se exporta público (`cn`) para que los consumidores mergeen igual que la librería.
- Compatibilidad 3.x (RNF-1): los defaults visuales no cambian salvo los bugs. `ghost` mantiene `border-2` y el borde de 1px va en una variante nueva `outline`. Textarea mantiene `inputClassName` como alias del elemento. El único cambio de comportamiento es `colorScheme` por defecto `default`, que va documentado en el CHANGELOG.
- Button sin wrapper solo cuando no hay tooltip: el drip ya es `absolute` dentro del `<button>` con `overflow-hidden`, así que no necesita el `<div>`. Con tooltip, el wrapper existe y recibe `wrapperClassName`.
- Release: minor `3.5.0` de la librería y minor del MCP (`0.11.0`) por las props nuevas en el registry; se publica recién con OK del dueño.
